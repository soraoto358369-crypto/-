# クオリティアップ — 「しょぼい」「もっと良くして」と言われた時の手順

ユーザーが「しょぼい」「単調」「ださい」「もっと良く」「クオリティ上げて」と言った時は、聞き返さずに次の順で診断→修正する。人向けの説明は `QUALITY-UP.html`（このファイルの内容 + プロンプト集）。

## 1. 診断（10項目。×を数える）

1. 1画面目に「絵」がある（KV 画像 / イラスト / 画面幅いっぱいの文字）
2. 1画面目に タイトル・比喩の一言・行動ボタン がある
3. 見出しは本文の3倍以上。名前と数字はさらに大きい
4. 強い色が「1か所だけ」（全部に塗っていない / 逆に1色も無い、を両方チェック）
5. スクロールで起きる演出が3つ以上（数字が回る / 見出しが現れる / 画像が動く / 判子・雷・破く など）
6. 数字（実績・価格・日数・本文中の数字）が動く
7. ボタンが脈打つ・影がある・文言が「手に入れる / 受け取る」系
8. スマホで 文字切れ・ボタンのはみ出し・タイマーの被り・勝手な揺れ が無い
9. 本人のアイコンか写真がある
10. 生成エンブレム・意味のない装飾が無い

×が付いた項目を、上から順に直す。1回の修正で直すのは最大3項目。直したら「直した3点」と「次に直せる点」を1行ずつ書く。

## 2. 直し方の対応表

| × の項目 | やること |
| --- | --- |
| 1・2 | KV を1枚作る（比喩から）。比喩が無ければ brief から3候補出して1つ採用。タイトルを画面幅いっぱいの極太に。ボタンを1画面目に |
| 3 | 見出し clamp(28px,4.5vw,64px) 以上、名前・数字は 1.5〜2倍。本文は 15〜17px |
| 4 | World のトークンに戻す。強い色は accent 1つ、金は数字1か所か線1本 |
| 5 | 各セクションに1つ: 見出しのマスク出現 / 数字カウント / 画像の視差 / 見出し下線ドロー。シグネチャーを1つ（signatures.md） |
| 6 | 数字を `<span class="js-count" data-to="N">` で包む（文章は変えない）。カウントダウンがあれば先頭固定・大きく・金 |
| 7 | `.btn--pulse`、影、ホバーで弾ける粒。文言は brief の goal に合わせて「手に入れる / 受け取る / 参加する」 |
| 8 | スマホ幅で `.btn{max-width:100%;white-space:normal}`、タイマー高さの変数、`shake/parallax` を touch で無効、iframe は静止画に |
| 9 | `icon:` があれば金の輪で中央に。無ければユーザーに「アイコンかSNSのURLをください」と1回だけ聞く |
| 10 | 消す。代わりにアイコン / 抽象の色面 / 文字の透かし |

## 3. ユーザーの言い方 → 解釈

| 言い方 | 解釈 |
| --- | --- |
| しょぼい / 単調 / 物足りない | 診断1〜7。画像と演出の密度を上げる。方向性は変えない |
| ださい | 診断4・10。象徴物・装飾・派手な色を消し、文字主役に戻す |
| うざい / 被る | 中央に出る演出・画面の揺れ・重なる要素を消す。ゲージなど端の演出は残す |
| effect 増し増し / 動きがほしい | 診断5・6を全部入れる。ただしスマホでは揺れ・視差を切る |
| もっと強調 / 太字に | em を 900 + 1.08em + 下線。赤=恐怖・問題提起、金=数字・ベネフィット |
| 文字を小さく | 読ませる段落は見出し扱いをやめて本文サイズ + 行間 1.8 |
| かっこよく / 唯一無二 | 比喩を1つ決め直し、KV と演出をそれに寄せる。参考サイトが無ければ muuuuu.org を提案 |
| GPT に投げてクオリティ上げて | 気に入った案の構図を保ったまま画像だけ再生成（背景のみ生成し、文字は CSS で載せる） |

## 4. 最初から良くするために聞くもの（1回だけ）

参考サイト1〜3本 / 嫌いな見た目 / 本人のアイコン / 実績の数字 / SNS・note の URL / 方向性の番号（①〜⑩）。素材貼り付け（1-d）で来た時はここが埋まる。
