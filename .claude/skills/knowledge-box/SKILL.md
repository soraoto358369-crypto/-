# ナレッジBOX

資料をそのまま残す「保管庫」と、資料から1話ずつ書き出した「カード」を分けて持つ。仕事のたびに、要るカードだけを読む。

使う人はパソコンに詳しくない社長だと考える。専門用語を避け、作業の結果だけを短く伝える。

このファイルがあるフォルダを `SKILL_DIR` と呼ぶ。道具はすべて次の形で動かす。箱の場所が今いるフォルダの `ナレッジBOX` でなければ `--box <場所>` を付ける。

```bash
python3 "$SKILL_DIR/scripts/box.py" <命令>
```

## 守ること

- 資料に無いことをカードにしない。推測は確かさを「予想」にする。「予想」のカードは取り出しに使わない。
- 保管庫の資料を書き換えない、消さない。
- 他の人の発信から借りてよいのは、話の順番だけ。文章、例え話、実績、独自の名前は写さない。
- 買った教材、受講生限定の資料、社外秘の資料は、本人が使う参考にとどめる。配布物や公開物へ中身を移さない。迷ったら持ち主を確認する。
- お客様の名前は「Aさん」「B社」に置き換える。メールアドレスと電話番号はカードへ書かない。
- パスワードやAPIの鍵（サービスに入るための秘密の文字列）をカードにも会話にも出さない。
- 箱の外へ送る、公開する、お金がかかる処理は、先に本人へ確かめる。

## 話しかけられたらやること

### 初めて使うとき

`init` を実行する。場所の指定が無ければ書類フォルダかデスクトップを本人に1回だけ確かめる。終わったら、受け箱の場所を伝えて「ここに資料を1つ入れて『入れて』と言ってください」と案内する。

### 「入れて」

1. 受け箱の資料が誰のものかを、まとめて1回だけ確かめる。
   - 自分: 自社の録画、メール、相談メモなど
   - 許可あり: 持ち主から使ってよいと言われたもの
   - 公開情報: 他の人が公開している投稿や動画の文字
2. `file --owner <持ち主>` を実行する。持ち主が混ざるなら、分けて入れてもらう。
3. 録音、録画、画像、PDFは、保管先の隣に `元の名前.txt` として文字にする。自分のパソコンで文字起こしできる道具（Whisperなど）を優先する。お客様の声が入った音声を外部のサービスへ送る場合は、先に確かめる。文字にできないときは、本人にテキストを貼ってもらう。
4. Googleドライブなどがつながっている環境では、本人が指定したフォルダや期間だけを読み取り、受け箱へ保存する。

### 「カードにして」

1. `todo` で資料を確かめ、1件ずつ読む。読み方は `references/card-guide.md` に従う。
2. 1行1枚のJSONにして `add --file <一時ファイル>` で追加する。
3. はじかれた行は、理由に沿って直して入れ直す。件数を増やすために言い換えを足さない。
4. 読み終えた資料を `done <保管先>` で済みにする。
5. 「何枚できて、どの棚が少ないか」を `stats` の結果から2行で伝える。

### 「〇〇のカードを出して」、または文章を書く前

1. `pick --recipe <レシピ名>` で取り出す。テーマがあれば `--tag 集客,LINE` のように足す。
2. 取り出したカードだけを材料に書く。別の棚を勝手に読まない。
3. 「カードなし」の部分は想像で埋めない。書かずに進めるか、本人に聞く。
4. 書き終えたら、使ったカードの番号を最後に1行で示す。

レシピが無い仕事は、本人に聞かずに近いレシピを元に `レシピ/<仕事の名前>.md` を作る。形は次のとおり。

```text
上限: 5000
お客様/悩み: 5
わたし/口調: 4
読まない: 商品/価格
```

`読まない` には、混ぜると文章がぶれるものを必ず書く。

### 「箱を点検して」

`check` を実行する。「直す」は自分で直してもう一度実行する。保管庫の資料が変わっている場合だけは本人に報告する。「確認」は件数を短く伝える。

### 他のスキルから使うとき

他のスキルには、カードのフォルダを丸ごと読ませない。そのスキルの手順に `pick --recipe <レシピ名>` を実行する一文を書き足してもらう。
